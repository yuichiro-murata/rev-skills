プロジェクト横断で再利用する Claude Code 基本設計Revスキルを管理するリポジトリ。 方式A：プラグイン・マーケットプレイス形式で配布する。

各プロジェクトはこのリポジトリをマーケットプレイスとして登録し、プラグイン（スキル群）を有効化する。

## スキル構成

単一プログラムの設計書ワークブックを対象とするチェックスキルは6つある。

| skill | チェック内容 |
|-------|------------|
| `design-doc-internal-consistency` | 設計書内部の相互参照（ｲﾍﾞﾝﾄ⇔処理概要、各ID登録、画面3点一致、排他制御） |
| `design-doc-io-table-check` | Ⅲ．入出力定義（CRUD一覧）の双方向網羅性 |
| `xlsx-db-column-check` | 参照ｶﾗﾑがﾃｰﾌﾞﾙﾚｲｱｳﾄに実在するか／ｺｰﾄﾞ・名称の二重保持 |
| `naming-standard-compliance` | 各ID採番規則・設計書記述ルール準拠 |
| `design-doc-formatting-consistency` | ﾌｫﾝﾄｻｲｽﾞ／ｾﾙ結合のブレ |
| `design-doc-typo-check` | 日本語の誤字脱字・変換ミス |

## REV実行時のチェック項目選択

以前は「REVして」と依頼すると上記6スキルが**無条件で全件実行**されていた。各チェックはワークブックの
ダンプ・DB設計書の突合を伴い個別に重いため、必要のないチェックまで走ると時間とトークンを浪費する。

そのため、フルREVの入口として `rev-program-review` スキルを追加した。動作は次の通り。

1. 対象ワークブックを確定する
2. `AskUserQuestion`（`multiSelect: true`）で6チェックをチェックボックス提示し、**実行前に**実施する
   チェックを選択させる（1問あたり最大4選択肢というツール制約に合わせ、整合性系4件／誤字・体裁2件の
   2問に分割。2問は1回の呼び出しで同時提示するため、6項目のチェックボックスが1プロンプト内に並ぶ）
3. 選択されたチェックのみを1パスで実行（ワークブックのダンプは先頭で1回だけ行い各チェックで共有）
4. 実施チェック／未実施チェックを明記した1本のレポートで報告

以下の場合は選択プロンプトを省略する。

- ユーザーが実施したいチェックを明示している場合（例:「入出力定義と誤字だけ見て」）→ そのチェックのみ実行
- ユーザーが「全部」「フルREV」等を明示した場合 → 6件すべて実行
- 個別スキルを名指しで起動した場合 → そのスキル単独で実行
- 非対話（バッチ／サブエージェント）で `AskUserQuestion` が使えない場合 → 6件すべて実行し、
  「選択できなかったため全件実行した」旨をレポートに明記
