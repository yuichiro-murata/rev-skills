プロジェクト横断で再利用する Claude Code の基本設計スキル（設計書レビュー／総合テスト仕様書作成）を管理するリポジトリ。 方式A：プラグイン・マーケットプレイス形式で配布する。

各プロジェクトはこのリポジトリをマーケットプレイスとして登録し、プラグイン（スキル群）を有効化する。

## プラグイン構成

このマーケットプレイスは用途の異なる2プラグインを配布する。プロジェクトごとに必要な方だけを
有効化できるよう、レビュー（既存設計書を検査する）と生成（設計書から成果物を作る）を分けている。

| plugin | 内容 |
|--------|------|
| `rev-skills` | 設計書レビュー(REV)。単一プログラムの設計書ワークブックを対象とする8つのチェックスキルと、その入口となる `rev-program-review` |
| `test-spec-skills` | 総合テスト仕様書作成。`integration-test-spec-generate` が設計書から総合テスト仕様書／報告書(.xlsm)を生成する |

## rev-skills のスキル構成

単一プログラムの設計書ワークブックを対象とするチェックスキルは8つある。

| skill | チェック内容 |
|-------|------------|
| `design-doc-internal-consistency` | 設計書内部の相互参照（ｲﾍﾞﾝﾄ⇔処理概要、各ID登録、画面3点一致、排他制御） |
| `design-doc-io-table-check` | Ⅲ．入出力定義（CRUD一覧）の双方向網羅性 |
| `xlsx-db-column-check` | 参照ｶﾗﾑがﾃｰﾌﾞﾙﾚｲｱｳﾄに実在するか／ｺｰﾄﾞ・名称の二重保持 |
| `naming-standard-compliance` | 各ID採番規則・設計書記述ルール準拠 |
| `update-condition-completeness` | 更新条件表の網羅性（NOT NULL／主キー／共通項目の設定漏れ、登録日時のUPDATE上書き） |
| `report-design-check` | 帳票設計書（帳票一覧登録、Ⅱ．帳票仕様の記入漏れ、参照先ｴｲﾘｱｽ、取得項目⇔印字項目） |
| `design-doc-formatting-consistency` | ﾌｫﾝﾄｻｲｽﾞ／ｾﾙ結合のブレ |
| `design-doc-typo-check` | 日本語の誤字脱字・変換ミス |

## REV実行時のチェック項目選択

以前は「REVして」と依頼すると上記スキルが**無条件で全件実行**されていた。各チェックはワークブックの
ダンプ・DB設計書の突合を伴い個別に重いため、必要のないチェックまで走ると時間とトークンを浪費する。

そのため、フルREVの入口として `rev-program-review` スキルを追加した。動作は次の通り。

1. 対象ワークブックを確定する
2. `AskUserQuestion`（`multiSelect: true`）で8チェックをチェックボックス提示し、**実行前に**実施する
   チェックを選択させる（1問あたり最大4選択肢というツール制約に合わせ、整合性系4件／更新・帳票2件／誤字・体裁2件の
   3問に分割。3問は1回の呼び出しで同時提示するため、8項目のチェックボックスが1プロンプト内に並ぶ）
3. 選択されたチェックのみを1パスで実行（ワークブックのダンプは先頭で1回だけ行い各チェックで共有）
4. 実施チェック／未実施チェックを明記した1本のレポートで報告

以下の場合は選択プロンプトを省略する。

- ユーザーが実施したいチェックを明示している場合（例:「入出力定義と誤字だけ見て」）→ そのチェックのみ実行
- ユーザーが「全部」「フルREV」等を明示した場合 → 8件すべて実行
- 個別スキルを名指しで起動した場合 → そのスキル単独で実行
- 非対話（バッチ／サブエージェント）で `AskUserQuestion` が使えない場合 → 8件すべて実行し、
  「選択できなかったため全件実行した」旨をレポートに明記

「Other」を選択して**何も入力しなかった場合**は「その観点は実施しない」と解釈し、そのグループの
チェックを全件スキップする（再質問しない）。3グループともチェックが無くなった場合は、全件実行に
フォールバックせず、ワークブックのダンプも行わずに停止し「チェックを実施しなかった」旨を明示する。
